# Lecciones activas (máx. 20)

1. **Verificación = login explícito por identidad, nunca la sesión del navegador.** Toda verificación arranca borrando las cookies `sb-*` y escribiendo la sesión de UNA identidad de la plantilla (magic link → cookie); se comprueba el email de la sesión antes de operar y se borran las cookies al terminar. Da igual que el navegador ya traiga la sesión del usuario (o de Haizea): no se usa y, si estorba, se sustituye. (Corrección del usuario, 2026-09-19.) Ojo: quitar el `#hash` de la URL no recarga la página; forzar una carga completa antes de mirar.
2. **Mutaciones desde caché pisan cambios ajenos.** Un `update` que reescribe todos los campos de una fila cacheada (edición inline) machaca lo que otro admin cambió entretanto. Las mutaciones compartidas escriben SOLO los campos presentes.
3. **`toISOString().slice(0,10)` sobre un `Date` local es un bug en Madrid** (devuelve el día anterior). Usar `src/lib/fechas.ts` (`hoyMadrid`, `sumarDias`, `ultimoDiaMes`); cálculo de calendario aritmético con `Date.UTC`.
4. **Una huella SHA cruda de RPCs puede cambiar sin cambiar los datos** (orden de filas empatadas tras un `UPDATE`). Compararla junto a la huella canónica (arrays ordenados). Regresión vigente: canónica `6c50f784`. Desde la 021 los `order by` de `resumen_dia/mes` desempatan (`nombre, id`): la cruda es estable (`fab8021d`); si se mueve sin cambio de datos, es un bug.
5. **Un cambio "de solo UI" que abre un formulario a un rol nuevo obliga a probar la RLS con intentos reales** (API directa), no solo lo que la UI deja hacer (así apareció que un admin_empresa podía subirse a admin_grupo; cerrado en la 021). Para reglas que comparan valor viejo/nuevo ("no se puede cambiar X") RLS no sirve: trigger `BEFORE UPDATE OF col` con `IS DISTINCT FROM`, y decidir por escrito si service_role queda exento (los triggers sí le aplican; `auth.uid()` es null). Todo control de UI que la BD rechaza se deja de renderizar, no se deja al error de BD.
6. **`window.confirm` bloquea el navegador automatizado**: sustituirlo por un stub que registra el mensaje y devuelve true/false.
7. **Los `sed`/heredocs con barras invertidas o comillas en Git Bash se rompen**: escribir scripts con la herramienta Write y ejecutarlos.
8. **Un clic por `ref` puede no disparar el `onClick`** (visto con «Guardar cambios» y «Analizar archivo»): comprobar siempre el efecto (BD o mensaje) y, si no llegó, repetir con clic por coordenadas tras `scroll_to`/captura.
9. **service_role salta RLS Y los triggers de guarda que exentan a service_role**: toda server action que lo use debe replicar en TS ámbito de empresa Y límites de rol, con LISTA BLANCA de roles (no lista negra de `admin_grupo`) y con la acción sobre la cuenta ajena (restablecer contraseña) tan restringida como cambiar su rol. Reglas en un helper puro (`lib/usuarios/permisos.ts`) que comparten servidor y UI. Se prueba con sesión real y cliente manipulado (forzar `<option>`/`disabled`), no con lo que la UI ofrece.
10. **RLS no da error, da 0 filas**: una guarda por USING (022) deja el UPDATE «con éxito» y sin efecto. La UI no ofrece lo que la BD va a silenciar y todo `update` cliente pide `.select('id')` y trata 0 filas como error, nunca un falso «guardado». Reglas de la UI en el helper compartido (`permisos.ts`); si una condición gobierna varias cosas (edición de perfil vs. resolver ausencias), separarlas antes de cambiarla.
11. **NORMA C — una sonda «inocua» debe fallar también para el rol AUTORIZADO**: probé `cerrar_periodo` como admin_grupo con una empresa real y escribió un periodo. Toda sonda de una RPC con efectos usa parámetros inválidos o inocuos (mes 13, ids inexistentes, listas vacías, `fin < inicio`), nunca datos válidos de demo; conteos antes/después; rutas positivas solo con cuentas de prueba y reversión. Material de subagentes: verificar en la BD real las afirmaciones graves antes de escribirlas (así se confirmó el hueco de `anon`).
12. **`supabase config push` rellena con SUS defaults lo que `config.toml` no declara** (MFA off, `enable_confirmations` off, `otp_length` 6 en la 023): previsualizar SIEMPRE con `echo n | supabase config push`, fijar en el archivo los valores remotos que no se quieren tocar y aplicar solo cuando el diff sea exactamente lo pretendido. La config de Auth no viaja con las migraciones.
13. **Leer el catálogo real sin psql ni Docker**: una migración temporal (`NNN_probe_tmp.sql`) con un `do $$ … raise exception … $$` devuelve el resultado en el error de `db push` y la transacción aborta sin dejar nada; se borra el archivo después. Sirve para `pg_proc`/`proacl`/`has_function_privilege`/`pg_get_functiondef` y para probar guardas con `set local role` (siempre parámetros inválidos, norma C). Los grants de Supabase por defecto abren TODO a `anon`: toda función y tabla nueva se revisa con `has_function_privilege('anon', …)`.
